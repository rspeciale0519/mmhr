# 2026-11-23

### [06:20] Fix Cobalt iPhone width shrink-to-fit   (branch: cursor/cobalt-mobile-overflow-23f4 · commits: 530fac3)

**Synopsis:** The live develop preview rendered Cobalt in the left ~56% of an iPhone visual viewport. Decorative 1100px glow orbs with `right: -300` expanded document overflow to 690px; iOS Chrome shrink-to-fits that layout into 390px. Glows now paint inside a clipped layer so they cannot widen the document.

**What worked:** Evidence: `npm run type-check`, `npm run lint`, `npm test` (5,513 tests), `npm run build`, `npm run test:e2e` (15 Playwright routes at 375–430px). Manual: Chromium iPhone emulation measured `innerWidth`/`scrollWidth`/`visualViewport.width` = 390 after the fix (was 690/690/390 on the live preview).

**What did NOT work:** `overflow-x: clip` on `html` alone did not stop iOS/mobile Chromium from expanding the layout viewport. A Playwright check of `scrollWidth <= innerWidth` also misses shrink-to-fit, because `innerWidth` grows with the overflow; the guard compares against `visualViewport.width`.

**Artifacts:** `src/designs/cobalt/Glow.tsx`, `src/designs/cobalt/styles.css`, `e2e/cobalt-mobile-overflow.spec.ts`, screenshots in `/opt/cursor/artifacts/`.
