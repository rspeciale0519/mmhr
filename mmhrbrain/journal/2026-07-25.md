# 2026-07-25

### [17:05] Pulse: diagonal accent wash + dark/light dual theme   (branch: feature/foundations · commits: none — working tree)
**Synopsis:** Owner picked **Pulse** as the favoured direction (G3 not formally
closed — this is iteration on the front-runner, not a ratified choice). Two
changes: a bottom-left → top-right gradient in the existing accent, and a
second (light) theme on a nav toggle.

**What worked:**
- Wash implemented as a **viewport-fixed `.pu::before`** (`position: fixed;
  inset: 0; z-index: -1`) inside `isolation: isolate` on `.pu`, not a
  background on the element. Evidence: verified by screenshot at scrollY 0
  and 2600 on a 4856px page — the diagonal is identical at both depths. A
  page-attached `to top right` gradient over ~4.9k px would have degraded to
  a near-vertical wash; `background-attachment: fixed` was rejected because
  it silently falls back to scroll on iOS Safari.
- Dual theme via full tokenisation: every hard-coded colour in the file was
  replaced by a custom property, with `.pu[data-theme="light"]` overriding
  the token block only. Design.tsx became a client component
  (`useState<"dark"|"light">`) setting `data-theme` on the root div.
- Surfaces sorted into three categories so translucency stays coherent:
  translucent bands (`--veil`), solid grid modules (`--module`), one glass
  panel (`--glass`, the signature signal card). The 1px-gap grids keep an
  opaque cell because their hairlines are painted by the container
  background — translucent cells would have shown the line colour through.
- Light theme is not an inversion. Two inversions were needed and made:
  a band reads as a *deepening* on paper (`--veil: rgba(10,58,54,.05)`) where
  it is a *lift* in dark; and separation comes from shadow (`--lift`, `none`
  in dark) rather than hairlines.
- Contrast held against the *washed* background, not flat paper: `--muted`
  darkened #566871 → #4e616a because the most saturated corner of the bloom
  lowers the paper luminance enough to drop 4.5:1 (computed ≈4.21 at the
  worst corner before, ≈4.75 after). `--accent` set to #097061 for the same
  reason (the bright #2fe6c4 is ~1.4:1 on white and unusable as text).
- Verified: `npm run type-check` clean · `npm test` 16/16 pass ·
  `GALLERY_ONLY=1 npm run build` succeeds with `/designs/pulse` still SSG ·
  no horizontal overflow at 375px emulated (`scrollWidth === clientWidth`)
  in both themes · nav collapses to a single row on mobile.

**What did NOT work:**
- First mobile pass wrapped the nav onto two rows with the CTA orphaned at
  the left: the theme button's `margin-left: auto` consumed the auto margin
  that used to push `.pu-solid` right, and the label pushed total width past
  the 339px content box. Fixed by hiding `.pu-theme-label` ≤640px (glyph
  only; `aria-label` + `title` carry the meaning). Measured after: children
  at 144 + 32 + 117 px + 40px gaps = 333 ≤ 339.
- Next.js devtools shows "1 Issue" on the page — traced to a
  `cz-shortcut-listen` attribute a browser extension injects on `<body>`.
  Not our markup, not a regression.
- Lint reports 26 `no-require-imports` errors, all in vendored
  `.claude/hooks/**` (sync-managed, not hand-editable per Rule 11).
  Pre-existing; zero errors in `src/`.
