# MMHR completion goal

Revised 2026-09-08. This supplements the active goal, whose saved text cannot be replaced by the available tool.

Complete MMHR v2 and verify production. Preserve mandatory R0 through R9 requirements and the design gallery. Keep deferred requirements deferred.

Read AGENTS.md, project memory, canonical documents and approved plans. Verify status from code and checks. Later approved user decisions override older records.

Implement the confirmed customer journey: free registration; automatic private workspace access after verified identity, without administration rights; software-needs intake; an initial scorecard showing all approved vendor options with provider names masked; selection of up to five RFP contenders; a representative call or RFP form; MMHR review of capabilities and customization; recorded disclosure of provider names after that discussion and before RFP submission; approved distribution and response comparison; customer selection and a direct customer-provider contract. Customers do not pay MMHR; providers pay a commission or referral fee. Do not invent equal commission rates or other public claims.

This goal authorizes normal implementation, required dependencies, branches, commits, pushes, pull requests, merges, configuration, migrations, bootstrap, and deployment through existing approved accounts. Do not request routine approval again. Do not purchase services or create paid commitments. Ask before actions that could damage the device, operating system, or unrelated data. Never expose secrets or personal data. Authorization does not replace actual review evidence or verified identities.

Preserve the checkpoint and unrelated work. Inspect Git state first. Integrate accumulated work into develop through focused branches and pull requests. Exclude local settings, hooks, secrets and caches from commits.

Finish usable workflows in dependency order. Repair interrupted changes first. Restore local database testing without resetting Docker or deleting its data. Finish registration, identity synchronization and workspace access. Then deliver the customer journey as connected workflows.

Complete the remaining R1 administration and security; R2A marketing, consent, content and leads; R2B CRM, vendor data and search; R3 evaluation and ranking; R4 communications, documents and jobs; R5 replaceable AI adapters and human review; R6 demos, proposals and contracts; R7 finance; R8 customer success, reporting and administration; R9 operational readiness; and R0 public-claim and release controls. The customer journey sets priority, not reduced scope.

For each package, trace requirements to working screens, server operations, persisted data and meaningful tests. Verify authorization, RLS, immutable audit, organization isolation, idempotency, errors and relevant concurrency. Use additive migrations with recovery instructions. Run focused checks first, then affected standard gates. Run all standard gates before merging. Use real database and browser checks where required. Review each change independently and fix valid findings.

Keep a requirement-to-evidence ledger. Separate implemented code, tested workflows and release readiness. Placeholders, mocks, static SQL checks, skipped tests and old runs cannot prove live completion. Record gaps. Continue independent work when an environment fails.

Commit and push reviewed packages. Submit pull requests to develop, resolve valid feedback, and merge after required checks pass. Validate staging, migration compatibility, restoration, containment and rollback before production. Release develop to main only after evidence gates pass. Verify production routes, permissions, isolation, integrations, monitoring, accessibility and performance.

Finish only with evidence for every mandatory requirement and verified live production. Report missing credentials, owner evidence and external blockers. Never invent approvals or completion.
